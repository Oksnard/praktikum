# Материалы из документов

Владелец и руководитель могут выбрать «Прикрепить документ» на странице материалов. Сотрудники видят извлечённый текст и могут скачать оригинал своей компании. В AI передаётся только сохранённое поле `Material.text`, через существующий grounded pipeline; бинарный файл модели не отправляется. Текст после загрузки виден полностью, до создания задания.

Поддержаны `.docx` (основной документ OOXML, включая таблицы), `.doc` Word97–2003 (OLE/WordDocument), `.pdf` с текстовым слоем и `.txt`. Заголовки/колонтитулы, комментарии, рисунки, вложения, формулы и сложный порядок колонок не гарантированы; перед созданием задания проверьте показанный текст. OCR и RAG отсутствуют. PDF без достаточного текста, защищённые паролем и повреждённые документы отклоняются. Изображения внутри текста не распознаются. TXT: строгий UTF-8 (включая BOM), UTF-16LE/BE с BOM, при ошибке UTF-8 — Windows-1251; автоматическое определение других кодировок не заявлено.

Ограничения: один файл до5МиБ, название3–150 символов, извлечённый текст60–12000 символов. Длинный документ отклоняется с предложением разделить его, без сохранения усечённого материала. Multipart ограничен одним файлом и одним полем `title`, два parts; никакой tenant из тела не принимается. Расширение, MIME и сигнатура проверяются, TXT с сигнатурой другого поддержанного бинарного формата отклоняется. ZIP: максимум500 записей,20МиБ суммарного объявленного распакованного размера,5МиБ на запись, сжатие не более100:1, без шифрования, дубликатов/обхода пути/DOCTYPE/ENTITY. ZIP не распаковывается на диск.

Обработка идёт отдельным процессом:10 секунд wall time,8 секунд CPU для Python, stdout/stderr суммарно до1МиБ. Конвертер запускается в отдельной POSIX process group; жёсткий deadline/SIGKILL завершает всю группу, Promise не ждёт закрытия унаследованных pipe. При обычном выходе главного процесса оставшиеся потомки также завершаются. Watchdog проверяет суммарный RSS process group каждые100мс и завершает группу выше256МиБ; ошибка мониторинга также завершает обработку. Это периодическая проверка, возможен краткий перерасход между проверками; Linux дополнительно ограничивает адресное пространство Python512МиБ. Для PDF pypdf ограничен200 страницами,20МиБ декомпрессии zlib,2МиБ содержимого страницы до извлечения; при превышении12000 сырых символов дальнейшие страницы не обрабатываются и весь документ явно отклоняется, даже если trim мог бы уменьшить длину. Для публичной масштабной эксплуатации нужны лимиты конкурентности на gateway/worker и OS/container memory limits; MVP не является sandbox для произвольных файлов.

## Зависимости и эксплуатация

- Python3 (проверено3.14) с `pypdf==6.14.2`: `python3 -m pip install pypdf==6.14.2` в окружении сервиса. DOCX использует stdlib `zipfile`/`ElementTree`.
- macOS: системный `/usr/bin/textutil` для `.doc`; Linux: `antiword` в PATH, mapping `UTF-8.txt` (Debian/Ubuntu: `apt-get install antiword`). Poppler не требуется.
- `ps` в PATH используется watchdog. Python и конвертер должны запускаться от непривилегированного пользователя.
- `MATERIAL_UPLOAD_DIR`: абсолютный путь к приватному постоянному каталогу, вне web/public; default `.runtime/material-uploads` относительно cwd процесса API. Создаётся с0700, файлы с0600, UUID-имена; оригинальное имя хранится только как метаданные. Каталог не публиковать через nginx/static. Бэкапировать вместе с БД. Нужны мониторинг свободного места, политика хранения и операционная сверка orphan-файлов после внезапного завершения процесса. При обычной ошибке БД созданный файл удаляется; временные файлы удаляются в finally. При аварийном завершении процесса временные файлы могут остаться в системном tmp.
- Миграция `202611240006_material_attachments` добавляет nullable metadata, старые текстовые материалы продолжают работать. Физическое хранение за `FileStorage`; API не зависит от локального пути.
- Доступ: `POST /materials/upload` OWNER/MANAGER, `GET /materials/:id/file` OWNER/MANAGER/EMPLOYEE, tenant из сессии; чужой или отсутствующий файл404. BFF держит сессию в HttpOnly-cookie, проверяет Origin для upload по server-owned `PUBLIC_ORIGIN` (точный origin без завершающего слеша, например `https://assigned.trycloudflare.com`); forwarded-заголовки не используются как доверенный источник. Когда переменная не задана, локальная разработка допускает валидный loopback Host (`localhost`, `127.0.0.1`, `[::1]`) с тем же Origin; для публичного запуска переменная обязательна. скачивание private/no-store, nosniff, attachment. Gateway/Next limits должны пропускать multipart до6МиБ. Файл перед сохранением полностью проверяется; при недоступном storage пользователь получает503.

## Проверка

`pnpm --filter @praktikum/api exec tsx --test test/documents.test.ts`: реальные кириллические DOCX/DOC/PDF/TXT (UTF8/CP1251/UTF16), zip bomb, подмена формата, binary TXT, слишком большой/длинный файл, PDF без текста/с паролем/повреждённый, multipart413,401/403, tenant404, скачивание byte-for-byte, отсутствие orphan при ошибке БД и запрет произвольного storage path. Регрессии также проверяют внешний Origin при внутреннем Next URL, отказ для spoofed forwarding/чужого Origin, жёсткое завершение TERM-ignoring дерева процессов и суммарный RSS потомков, отказ для PDF с пробелами перед более поздними страницами. HTTP проверка использует настоящий Nest/AuthGuard/parser/filesystem, заменяя только DB adapter in-memory; браузерные сценарии проверяют реальный PostgreSQL отдельно. Fixtures в `apps/api/test/document-fixtures`; stdlib generator сохраняет текст/OOXML/PDF, DOC создан macOS textutil, encrypted PDF — pypdf.

Источники API: [NestJS multipart limits](https://docs.nestjs.com/techniques/file-upload), Context7 `/nestjs/docs.nestjs.com`; [Python ZIP](https://docs.python.org/3/library/zipfile.html); [pypdf text extraction and memory caveats](https://pypdf.readthedocs.io/en/stable/user/extract-text.html), Context7 `/py-pdf/pypdf`; [antiword CLI](https://manpages.debian.org/bookworm/antiword/antiword.1.en.html); macOS `man textutil`; [Next16 Route Handlers](https://nextjs.org/docs/app/api-reference/file-conventions/route), Context7 `/vercel/next.js/v16.0.3`.

## Облачный review с непостоянным диском

`MATERIAL_STORAGE=postgres` использует `StoredFile.data Bytes` в PostgreSQL; миграция7 ограничивает размер 1–5242880 байт. Tenant-проверка до чтения оригинала остаётся в DocumentsService. По умолчанию используется прежнее локальное хранилище. В cloud исходные файлы входят в `pg_dump`; прежний paired backup локального каталога без адаптации для этого провайдера не запускать. Общая квота blob-хранилища и удаление orphan после аварии не автоматизированы. [Cloud review](render-cloud-source.md).
