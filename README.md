# Практикум

Локальный MVP SaaS обучения сотрудников: материалы компании → практическое задание → содержательный ответ → оценка по стабильным критериям, цитаты, пробелы и персональное обучение. Реальный AI — DeepSeek по последнему запросу заказчика; OpenAI доступен как альтернативный провайдер. NestJS + Next App Router + PostgreSQL/Prisma, pnpm/Turborepo.

## Запуск

Требуется Node22+ (проверено25.9), pnpm10 и работающий PostgreSQL (проверено14). В этой рабочей папке БД уже запущена. Для нового локального окружения с установленным PostgreSQL доступен `sh scripts/local-db.sh` (init/start только loopback55432, данные в .runtime; не production).

```bash
cp .env.example .env                 # только при первом запуске, не затирайте существующий файл
# заполните DATABASE_URL и DEEPSEEK_API_KEY в .env
# AI_PROVIDER=deepseek; для OpenAI: AI_PROVIDER=openai и OPENAI_API_KEY
pnpm install
pnpm db:generate
pnpm db:migrate
pnpm db:seed
pnpm dev
```

Web: http://localhost:3000 — API health: http://localhost:3011/health . Port3001 оставлен существующему сервису. Ключ выбранного провайдера нужен только backend и хранится в игнорируемом `.env`. Без него AI возвращает явную503 до резервирования; генерация не симулируется. После изменения ключа или AI_PROVIDER перезапустите `pnpm dev`.

После seed пароль всех **локальных демонстрационных** аккаунтов `Praktikum2026!`:

| Роль | Альфа | Бета |
|---|---|---|
| OWNER | owner@alpha.test | owner@beta.test |
| MANAGER | manager@alpha.test | manager@beta.test |
| EMPLOYEE | employee@alpha.test | employee@beta.test |
| SUPER_ADMIN | admin@praktikum.test | — |

Две компании имеют по1000000 демонстрационных кредитов, исходный материал. Seed идемпотентен и не сбрасывает изменённые пароли/расходы. Не применяйте известные demo пароли в публичной среде.

## Проверка сценария

1. Войти owner@alpha.test или зарегистрировать новую компанию. В новом tenant пополнить баланс через явно помеченный Demo платёж минимум на200000.
2. Создать сотрудника и/или менеджера, задать лимит ≥200000. Добавить текстовый рабочий материал60–12000 символов и сгенерировать задание.
3. Войти сотрудником, прочитать источник и задание, написать содержательный ответ. Посмотреть score, критерии, дословные цитаты, unsupported claims, пробелы и персональный учебный текст.
4. Войти менеджером: посмотреть результаты сотрудников. Владелец видит историю и баланс. super-admin видит все движения и AI audit.
5. Для каждого AI действия200000 кредитов временно резервируется, затем возвращается неиспользованный остаток. Повтор успешного запроса не вызывает AI и не списывает повторно.1 кредит=1 microUSD внутреннего тарифа; стоимость по фактическим input/cache/output tokens округляется вверх на вызов. Внутренний тариф DeepSeek фиксирован на peak каталоге и может отличаться от счёта провайдера с off-peak скидкой: [ADR0010](docs/decisions/0010-deepseek-and-internal-tariff.md).

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm test:e2e          # HTTP + PostgreSQL, AI fixtures только через DI
pnpm evals            # 5 записанных реальных DeepSeek ответов, без внешнего API
pnpm evals --live     # выбранный провайдер; реальные вызовы либо успешный cache, аудит и списания
pnpm build
```

E2E создаёт отдельные tenants и удаляет только их в finally; не запускайте на production БД. Миграции — в git. Резервирует бюджет атомарно, paid invalid outputs тоже оплачиваются. Неизвестный сетевой outcome удерживает резерв, чтобы избежать повторного списания: сверка администратором описана ниже.

## Сопровождение и ограничения

MVP предназначен для локальной проверки. DeepSeek прошёл5 живых evals и полный HTTP сценарий с отображением результата в кабинете: оценка100/100,3 критерия,4 точные цитаты, рекомендации и результат у менеджера. Генерация и оценка списали1177 внутренних кредитов; повтор генерации не списал ничего.

DeepSeek гарантирует JSON mode, но не серверный strict json_schema: форму, цитаты и критерии проверяет приложение через Zod с максимум2 retry. Это явно согласованное изменение исходного ТЗ при выборе DeepSeek. Альтернативный OpenAI adapter сохраняет strict json_schema; его текущий аккаунт ответил429 credit_balance_exhausted, а модель gpt-4o-mini помечена Deprecated.

Нет SSO, reset password, отправки email, реальных платежей, файлов PDF, публичного деплоя. Application tenant isolation вместо RLS, с adversarial tests. Критерии хранятся в БД и snapshot assignment, редактор критериев не входит MVP. Сессии24ч, logout отзывает; локальные demo credentials известны. Эксплуатация публично требует production TLS/cookies, ограничение входа/регистрации, аудит/backup и секреты окружения. Оценки AI требуют человеческого контроля.

PENDING после process crash и UNKNOWN после неопределённого API исхода нельзя повторять автоматически. SUPER_ADMIN получает operation id/hash/calls/ledger через `/admin/ledger`. Сопоставьте usage с провайдером; подтвердив итоговую стоимость, в одной обслуживающей SQL транзакции запишите корректировку ledger с уникальным key, верните только разницу резерва/фактической стоимости в Company.balance/User.spent и зафиксируйте terminal operation status. Перед ручной корректировкой сделайте backup. Автоматический reconciler/UI корректировок вне MVP; никаких необоснованных возвратов при неизвестном usage.

При первоначальной проверке OpenAI остался один UNKNOWN с резервом100000: исход первого запроса не был подтверждён. Он сохранён для честного аудита; это не расход DeepSeek. Известный отказ провайдера теперь записывает безопасные status/code, освобождает неиспользованный резерв и допускает повтор с revision CAS. Ключи не входят в Git и браузер.
